# Спецификация модели, протоколов и валидации

Все значения в §3–§6 — стартовые. Калибруются на pilot (фаза 3), затем замораживаются в PREREGISTRATION.md. Время нормировано: E[S] = 1.

## 1. Что моделируем
Один сервис с пулом из c воркеров и очередью ёмкости K. Клиенты порождают первичные запросы пуассоновским потоком; на каждый запрос действует клиентский таймаут T и политика повторов. Запрос, у которого клиент отказался ждать (таймаут), может остаться в очереди и всё равно будет обработан («осиротевшая работа», wasted work), если не включена передача крайнего срока.

Нагрузка: ρ = λ · E[S] / c, где λ — интенсивность первичных запросов.

## 2. Жизненный цикл запроса
1. Первичный запрос в момент t. Попытка №0.
2. Если очередь заполнена (K), запрос отклоняется сразу (клиент видит ошибку, а не таймаут).
3. Иначе запрос ждёт в очереди и обслуживается по дисциплине Q.
4. Если до t + T ответ не получен или получен отказ, клиент считает попытку неудачной и по политике R планирует повтор (или сдаётся).
5. Если ответ получен до t + T, попытка успешна, остальные повторы этого запроса отменяются.
6. Передача крайнего срока (D = on): воркер, достав из очереди запрос с истёкшим клиентским сроком, пропускает его без обслуживания. При D = off обслуживает впустую.

Все попытки одного запроса учитываются как отдельные записи в очереди.

## 3. Параметры и факторы

Фиксированные (стартовые): c = 8, K = 128, T = 10, E[S] = 1.

| Фактор | Уровни |
|---|---|
| R, политика повторов | **R0** нет; **R1** фиксированная: до 3 повторов, задержка d = 1; **R2** экспоненциальная выдержка с полным джиттером: base = 1, множитель 2, потолок 16, до 3 повторов; **R3** = R2 + бюджет повторов (token bucket: повторов не более 10 % от первичных за скользящее окно 100, запас 10 токенов) |
| Q, дисциплина | **FIFO**; **LIFO**; **ALIFO** — адаптивный LIFO: FIFO, пока длина очереди ≤ θ_q·K (θ_q = 0,5), иначе LIFO |
| D, крайний срок | off / on |
| S, время обслуживания (среднее 1) | **Exp** (cv = 1); **LogN** (cv = 2); **Pareto** (α = 2,5, масштаб под среднее 1) |

Основная сетка: 4 × 3 × 2 × 3 = 72 конфигурации. Circuit breaker не входит в основную сетку (можно добавить как R4 только до заморозки).

## 4. Триггеры
- **Слабый** (для pilot и аналитики): всплеск λ × 2,5 на время D_w = 30.
- **Сильный** (определяет ρ_fold): всплеск λ × 4 на D_s = 50.
Параметры калибруются так, чтобы при R1 существовал ρ < 1 с P_A > 0, а при R0 система всегда восстанавливалась.

## 5. Метрики
- **Goodput-ratio g(t)** в окне W: доля первичных запросов, получивших успешный ответ до истечения срока, от числа первичных запросов в окне. Базовое окно W = 100.
- **Отказ (failed):** g < θ в последнем окне наблюдения. Стартовое θ = 0,5; чувствительность: 0,3 и 0,7.
- **Усиление повторов:** попыток на один первичный запрос.
- **Доля впустую потраченной работы:** время обслуживания запросов, чей клиент уже ушёл, / общее время обслуживания.
- **Время восстановления:** от конца триггера до первого момента, когда g ≥ 0,9 держится 50 единиц; цензурируется горизонтом.
- **p99 задержки** успешных запросов; траектория длины очереди (сэмплы раз в 1).

## 6. Протоколы измерения области бистабильности
Тестовая нагрузка ρ_test. Для каждого ρ_test две «истории», итоговое окно наблюдения одинаковое.

**Протокол A (путь «здоровый → отказ», ρ_fold).**
1. Разогрев при ρ_test до t₀ = 200.
2. Сильный триггер на [t₀, t₀ + D_s].
3. Возврат к ρ_test, наблюдение H_rec = 1500.
4. failed_A = 1, если g < θ в последних 300 единицах.

**Протокол B (путь «перегруженный → снижение», ρ_release).**
1. Работа при ρ = 1,05 в течение 1000 (система гарантированно в отказе; было 400, изменено 23.10.2026 предложение, подтверждено автором, ожидает подтверждения автора, см. DECISIONS D-017).
2. Мгновенное снижение до ρ_test, наблюдение H_rec = 1500.
3. failed_B = 1, если g < θ в последних 300 единицах.

**Оценка порогов.** P_A(ρ), P_B(ρ) — доли отказов по R реплик. Порог — ρ, при котором доля = 0,5: логистическая регрессия по ρ (при полном разделении — изотоническая регрессия), 95 % доверительный интервал bootstrap по репликам (≥ 2000 повторов).
- ρ_fold = порог по P_A; ρ_release = порог по P_B.
- **Δ = ρ_fold − ρ_release ≥ 0.** Δ > 0 означает область бистабильности. Если P_A < 0,5 на всей сетке до ρ = 1,0, ρ_fold = 1,0 (цензурировано, помечается).
Δ = 0 при R0 — контроль.

**Сетка ρ:** 0,40–1,00 с шагом 0,05, затем уточнение шагом 0,01 в окрестности порога. Реплик R = 30 на точку (pilot: 10). Итого ≈ 21 точка × 2 протокола × 30 × 72 ≈ 90 тыс. прогонов; точное число уточняется на G3.

## 7. Валидация (все V обязательны до G2)
- **V1.** R0, Exp, FIFO, c = 1, без триггера: средняя задержка и вероятность ожидания совпадают с формулами M/M/1; для c = 8 — с формулой Эрланга C. Отклонение в пределах 95 % ДИ репликаций; ρ = 0,5; 0,7; 0,9.
- **V2.** LIFO при экспоненциальном обслуживании: среднее время ожидания совпадает с FIFO (дисперсия больше). Проверка, что дисциплины реализованы корректно.
- **V3.** Режим «классическая система с повторными вызовами» (c = 1, K = 0, отклонённые уходят на орбиту, повтор с экспоненциальной интенсивностью ν): P(сервер занят) = ρ, а средняя длина орбиты совпадает с известной формулой (источники: Falin & Templeton 1997; Artalejo & Gómez-Corral 2008; теоретическая проверка выводит формулу и проверяет её независимо). Сверить также качественно с результатами томской школы (Назаров и др., см. refs/seed_references.md).
- **V4.** Баланс: первичные запросы = успехи + окончательные неудачи + отклонения + «в полёте»; никаких отрицательных времён.
- **V5.** Воспроизводимость: одинаковый seed → побайтово одинаковый результат; разные seed → разные.
- **V6.** Контроль отсутствия метастабильности: при R0 для всех ρ ≤ 0,95 после снятия триггера система восстанавливается (Δ ≈ 0).

## 8. Аналитическая опора (теоретическая проверка)
Mean-field приближение для R1 при экспоненциальном обслуживании: стационарная вероятность таймаута q(λ_eff) через время ожидания M/M/c, и эффективная нагрузка λ_eff = λ(1 + q + … + q^m) с учётом осиротевшей работы. Ищем неподвижные точки; несколько решений означают бистабильность. Это гипотеза о методе, а не известный результат: допущения и область применимости фиксируются в docs/THEORY.md. Предсказание ρ_fold/ρ_release из этой модели сравнивается с симуляцией (гипотеза H3).

## 9. Вычислительный бюджет
Замерь время одного прогона на типичной конфигурации. Если среднее > 1 с, оптимизируй (heapq/numba) до G2. Параллелизм: `joblib` или `multiprocessing`, по одному прогону на процесс, возобновление по списку выполненных (config_hash, ρ, protocol, seed).

## 10. Формат результата
parquet, одна строка = один прогон: config_hash, factors (R, Q, D, S), ρ_test, protocol, seed, failed, g_final, retries_per_request, wasted_fraction, recovery_time, p99, runtime, git_commit.

## 11. Ограничения модели (обязательны в статье)
Открытый пуассоновский вход; одно узкое место; нет сетевых задержек и корреляций; параметры синтетические, не калиброваны по продакшену; пороги зависят от θ, T, K и силы триггера. Результаты относятся к модели, а не к конкретной реальной системе.
