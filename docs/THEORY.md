# Теория: эталонные формулы и mean-field модель для R1

Код: `analysis/theory.py` (чистые функции, не зависят от `src/`), тесты `tests/test_theory.py` (39 тестов, ruff чист). Независимый мини-симулятор для сверки: `analysis/theory_check_sim.py` (FIFO, Exp, D = off, R1; не заменяет `src/`). График: `figures/theory_branches.{png,svg,csv}`; данные прототипа протоколов: `figures/theory_check_protocols.csv`.

Обозначения: μ = 1/E[S], a = λ/μ, ρ = a/c, C(c,a) — вероятность ожидания (Erlang C). Пометка **[источник]** означает, что страницу открыл теоретик и формула там есть; **[вывод]** — выведено здесь и проверено численно.

## 1. V1: M/M/1 и M/M/c (FIFO, R0, Exp)

Источник: https://en.wikipedia.org/wiki/M/M/c_queue (открыт), та же формула Эрланга C на https://en.wikipedia.org/wiki/Erlang_(unit) (открыт). Wikipedia — справочный источник; для статьи нужна ссылка на учебник (Kleinrock, Gross & Harris и т. п.), **не открывался, [НЕ ПРОВЕРЕНО]**.

- C(c,a) = [a^c/c! · 1/(1−ρ)] / [Σ_{k<c} a^k/k! + a^c/c! · 1/(1−ρ)], ρ < 1 **[источник]**. В коде вычисляется через рекурсию Эрланга B (устойчиво).
- W_q = C / (cμ − λ); W = W_q + 1/μ **[источник]**.
- M/M/1 (c = 1): C = ρ, W_q = ρ/(μ−λ), W = 1/(μ−λ) **[источник]** (подстановка).
- Хвост ожидания FIFO: P(W_q > t) = C·exp(−(cμ−λ)t) **[вывод]**: по PASTA прибывшая попытка застаёт n ≥ c в системе с вероятностью C, условное распределение n−c геометрическое с параметром ρ, ожидание — сумма n−c+1 экспоненциальных(cμ), то есть геометрическая сумма = Exp(cμ(1−ρ)). Проверено: ∫ хвоста = W_q, совпадение с распределением из birth-death (тест).

Эталонные значения (E[S] = 1), для V1:

| c | ρ | P(ожидание) | W_q | W |
|---|---|---|---|---|
| 1 | 0,5 | 0,5 | 1,0 | 2,0 |
| 1 | 0,7 | 0,7 | 2,3333 | 3,3333 |
| 1 | 0,9 | 0,9 | 9,0 | 10,0 |
| 8 | 0,5 | 0,059044 | 0,014761 | 1,014761 |
| 8 | 0,7 | 0,270603 | 0,112751 | 1,112751 |
| 8 | 0,9 | 0,701533 | 0,876916 | 1,876916 |

Замечания для валидация: (i) «P(ожидание)» при c = 8 — это именно P(все воркеры заняты в момент прихода) = C (PASTA); (ii) при ρ = 0,9, c = 1 автокорреляция велика, ДИ репликаций широкий, нужен длинный прогон или метод батчей; (iii) конечная очередь K = 128 при ρ ≤ 0,9 даёт блокировку порядка 1e-6 и ниже (≈ C·ρ^128 для c = 8), поэтому формулы M/M/c применимы без поправки; допустимо также задать K = ∞ в V1.

## 2. V2: LIFO против FIFO при экспоненциальном обслуживании

**Среднее.** [вывод] При экспоненциальном обслуживании число в системе N(t) — одна и та же цепь рождения и гибели для любой дисциплины, не использующей размер заявки и сохраняющей работу (интенсивность ухода = min(n,c)μ зависит только от n). Значит E[N] одинаково, и по формуле Литтла среднее время в системе и ожидания одинаково для FIFO и LIFO (также ALIFO, пока он не использует оставшееся/известное время обслуживания). Это распространяется и на M/M/c, и на M/M/c/K для времени, усреднённого по принятым. Для **T-зависимых** величин (P(W+S ≤ T), p99) дисциплина важна: распределение различается.

**Дисперсия (M/G/1, невытесняющий LIFO).** Источник: Finch S., *M/D/1 Queues with LIFO and SIRO Policies*, arXiv:2208.09980, https://arxiv.org/abs/2208.09980 (PDF открыт, формулы прочитаны). Пусть ξ = E[S²], η = E[S³]:
- среднее (FIFO = LIFO) = λξ / (2(1−ρ));
- дисперсия FIFO = λη/(3(1−ρ)) + λ²ξ² / (4(1−ρ)²);
- дисперсия LIFO = λη/(3(1−ρ)²) + λ²ξ²(1+ρ) / (4(1−ρ)³).
В статье приведены числа M/D/1 (λ=2, μ=3): среднее 1/3, дисперсия LIFO 7/9, FIFO 5/27, и M/M/1 (λ=2, μ=3): среднее 2/3, LIFO 32/9, FIFO 8/9. Код воспроизводит их (тест `test_finch_*`). Для M/M/1 подставляется E[S^k] = k!/μ^k. Для c > 1 замкнутой формулы дисперсии я не открывал: проверка V2 при c = 8 только по среднему (должно совпасть) и по знаку (дисперсия LIFO больше). Тот же вывод «среднее равно» в статье Finch сформулирован для M/D/1 и SIRO; общий случай выше выведен мной.

Независимая проверка: тест `test_lifo_equals_fifo_mean_larger_variance_mm1` (M/M/1, ρ = 0,5, 3·10⁵ заявок: средние совпадают с теорией в пределах 4 %, дисперсии FIFO и LIFO — 8 % и 15 %).

Ограничение для V2: дисперсия LIFO имеет тяжёлый хвост, оценка по ограниченной выборке шумная; сверять **среднее** (жёсткий критерий) и **p99/дисперсию качественно**.

## 3. V3: классическая система с повторными вызовами M/M/1, K = 0

Модель: пуассоновский вход λ, сервер Exp(μ), мест ожидания нет; заявка, заставшая сервер занятым, уходит на орбиту и повторяет попытку независимо от остальных с интенсивностью ν (всего nν при n на орбите, «классическая» политика). Источник определения политик: Daduna H., *Alternating birth-death processes*, arXiv:2004.08816, https://arxiv.org/abs/2004.08816 (PDF открыт, §2.1.1: ν_n = ν·n, ссылка на Falin 2013 и Artalejo & Gómez-Corral 2008). Фалин и Темплтон (1997) и Артахело, Гомес-Корраль (2008) как книги **не открывались [НЕ ПРОВЕРЕНО]**; формулы ниже выведены мной и сверены с формулой Фалина из Daduna (2.13).

- Устойчивость: ρ = λ/μ < 1 (для классической политики) [вывод; ссылкой на книгу не подтверждено].
- P(сервер занят) = ρ [вывод]: баланс потока (каждая заявка обслуживается один раз, интенсивность завершений μ·P(занят) = λ). Тест: численное решение даёт ρ с точностью 1e-9.
- Стационарное совместное распределение занятых состояний [источник: Daduna (2.13)]: P(n, занят) ∝ ρ^{n+1} ∏_{k=1..n}(λ+kν)/(kν), т. е. отрицательное биномиальное: P(n, занят) = ρ(1−ρ)^{1+α} ρ^n (1+α)_n / n!, α = λ/ν (нормировка на P(занят) = ρ). Тест с численным решением совпадает (rtol 1e-6).
- **Средняя длина орбиты** E[N] = ρ(ρ + λ/ν) / (1 − ρ) [вывод]. Вывод: (а) среднее NB(1+α, ρ) равно (1+α)ρ/(1−ρ), поэтому E[N·1{занят}] = ρ²(1+α)/(1−ρ); (б) поток в орбиту λ·P(занят) = λρ равен потоку из орбиты ν·E[N·1{свободен}], откуда E[N·1{свободен}] = αρ; (в) сумма = ρ(ρ+α)/(1−ρ). Проверка: решение уравнений равновесия на усечённом пространстве (n ≤ 1200, numpy) для (λ,ν) = (0,5;1), (0,7;0,5), (0,9;2), (0,5;0,25) даёт E[N] = 1,0000; 4,9000; 12,1500; 2,5000 с относительной ошибкой ≤ 1e-5. Предельный случай ν → ∞ даёт ρ²/(1−ρ) (очередь M/M/1) — тест.
- Среднее время на орбите по Литтлу E[N]/λ.

Что в V3 спецификации нужно уточнить: «P(занят) = ρ» верно только при ρ < 1 и в стационаре; сравнивать **долю времени занятости** сервера, а не доли отклонённых; при малых ν орбита велика (E[N] ≈ ρ·λ/(ν(1−ρ)) при ν → 0), нужен длинный прогон и тест на стационарность.

## 4. Mean-field для R1

### 4.1 Модель (вывод теоретика, основана на гипотезе MODEL_SPEC §8)

Параметры: c = 8, T = 10, E[S] = 1, R1: m = 3 повтора, пауза d = 1, FIFO, D = off, S ~ Exp.

1. q — вероятность неудачи одной попытки (таймаут или отказ из-за полной очереди). Попытка k+1 существует только если k-я неудачна. Среднее число попыток на запрос: Σ_{k=0..m} q^k. Интенсивность попыток λ_eff = λ·Σ_{k=0..m} q^k.
2. Осиротевшая работа (D = off): каждая принятая попытка обслуживается целиком, поэтому нагрузка сервера ρ_eff = λ_eff·E[S]/c включает осиротевшие попытки; принятый поток — пуассоновский (допущение) с интенсивностью λ_eff.
3. Вероятность успеха попытки s(λ_eff) = P(W + S ≤ T), q = F(q; ρ) = 1 − s(λ_eff(q)). Неподвижная точка: q = F(q; ρ).
4. Два варианта s:
   - **(§8, K = ∞)** M/M/c с бесконечной очередью. W = 0 с вероятностью 1−C, иначе Exp(θ), θ = cμ−λ_eff; S ~ Exp(μ) независимо. P(W+S > T) = (1−C)e^{−μT} + C·(μe^{−θT} − θe^{−μT})/(μ−θ) (θ ≠ μ). При ρ_eff ≥ 1 по определению s = 0 (q = 1).
   - **(уточнение, K = 128)** M/M/c/(c+K): состояния n = 0..c+K, π_n — стационарное распределение birth-death, PASTA. Принятая попытка (n < c+K) застаёт n в системе: при n < c ожидания нет, при n ≥ c W ~ Erlang(n−c+1, cμ). s = Σ_{n<c+K} π_n·P(W_n + S ≤ T); отказ при n = c+K считается неуспехом. Замкнутая форма: P(W_n+S ≤ T) = P(W_n ≤ T) − e^{−μT}(r/(r−μ))^j·γ(j,(r−μ)T) (r = cμ, j = n−c+1, γ — регуляризованная нижняя неполная гамма; c = 1 — Erlang(j+1,μ)). Проверено: при K → ∞ совпадает с вариантом §8 (1e-9); для c = 1 — с численным интегрированием; против независимой симуляции пуассоновского входа (ρ = 0,97, K = 128): доля неуспеха 0,090 ± 0,009 против 0,0919 по формуле (при K = ∞ формула давала бы 0,108, то есть конечная очередь существенна около насыщения).
5. Устойчивость решения (эвристика): F'(q*) < 1 (итерации q_{n+1} = F(q_n) сходятся). F монотонна по q, поэтому устойчивые и неустойчивые решения чередуются.
6. Goodput-ratio модели: g = 1 − q^{m+1}. «Отказ» при θ = 0,5: g < 0,5. Пауза d и таймаут T влияют на динамику, но не на стационарное уравнение (q — только через T в P(W+S ≤ T)).
7. Критерий бистабильности: при некотором ρ существуют ≥ 2 устойчивых решения. Границы области в модели (спинодали): ρ_fold^MF — наибольшее ρ, при котором существует устойчивая «здоровая» ветвь (g ≥ θ); ρ_release^MF — наименьшее ρ, при котором существует устойчивая «отказная» ветвь (g < θ).

### 4.2 Результаты для базовых параметров

Решения (K = 128): ρ = 0,2 — единственное q ≈ 4,5e-5 (≈ P(S > T) = e^{−10}); ρ = 0,5 — q ≈ 0 (уст.), 0,5487 (неуст.), ≈1 (уст.); ρ = 0,7 — 1e-4 (уст.), 0,2995 (неуст.), 1 (уст.); ρ = 0,9 — 0,0011 (уст.), 0,0676 (неуст.), 1 (уст.); ρ = 1,0 — только q ≈ 1. График: `figures/theory_branches.png`, левая панель.

| Вариант | ρ_release^MF | ρ_fold^MF | Δ^MF |
|---|---|---|---|
| K = ∞ (§8) | 0,2500 (= 1/(m+1), точно: при q = 1 нагрузка (m+1)ρ ≥ 1) | 0,9281 | 0,678 |
| K = 128 | 0,2772 | 0,9285 | 0,651 |

Бисекция с допуском 1e-4 (на сетке q из 1001 точек). Эти числа — границы устойчивости детерминированной модели.

**Важное расхождение со спецификацией (учтено в спецификации).** ρ_fold протокола A — это не спинодаль ρ_fold^MF. Спинодаль — это ρ, где исчезает сама здоровая ветвь; протокол A с конечным триггером измеряет границу бассейна притяжения, она лежит между ρ_release^MF и ρ_fold^MF и зависит от силы триггера (MODEL_SPEC §6 это признаёт для пороговых значений). Прототип (независимый мини-симулятор, K = 128, T = 10, R1, 30 реплик, θ = 0,5, H_rec = 1500, окно 300):

| триггер | ρ(P_A = 0,5) | ρ(P_B = 0,5) |
|---|---|---|
| ×4 на 50 (спецификация) | ≈ 0,34 | ≈ 0,33 |
| ×2 на 50 | ≈ 0,59 | ≈ 0,33 (тот же протокол B) |

То есть при триггере из спецификации (×4, D_s = 50) в прототипе Δ ≈ 0 (в пределах ±0,02, шум реплик), а при триггере ×2 Δ ≈ 0,26. Грубое флюидное объяснение (эвристика, не проверена как предсказание): триггер оставляет очередь, превышающую T·c = 80, если c(κρ−1)D_s ≳ 80 (κ — множитель); для κ = 4, D_s = 50 это ρ ≳ 0,30; для κ = 2 — ρ ≳ 0,70 (наблюдается 0,59, то есть эвристика грубая). Вывод для калибровки на pilot: Δ определяется силой триггера; при «сильном» триггере область бистабильности схлопывается к ρ_release. Решать калибровкой (слабее триггер или иное D_s), а не править теорию. Это прототип: числа не из `src/`, не из pilot и не должны попадать в статью.

### 4.3 Сравнение модели и прототипа: что подтвердилось, что нет

- Подтвердилось (качественно и количественно): существование отказной ветви и её порог по ρ около 1/(m+1) ~ 0,25–0,33; P_B(ρ ≤ 0,25) = 0, рост около 0,3.
- **Расхождение, не подгонялось:** ρ_release^MF = 0,277 ниже, чем порог P_B = 0,5 в прототипе (≈ 0,33). При ρ = 0,30 модель считает отказную ветвь устойчивой, прототип при H_rec = 1500 даёт P_B = 0,13; при H_rec = 6000 — 0,0; при ρ = 0,33 доля 0,5 (H = 1500) и 0,1 (H = 6000). То есть в симуляции отказное состояние лишь метастабильно (конечное время жизни, c = 8 — шум не мал), порог зависит от горизонта; детерминированная модель этого не описывает. Это свойство метрики (P_B зависит от H_rec), нужно записать как ограничение/чувствительность.
- Модель не предсказывает ρ_fold протокола A (см. выше); для H3 («ρ_fold^theory против ρ_fold^sim») нужно либо сравнивать спинодаль только с тем, что она реально описывает (устойчивость здоровой ветви без триггера, при ρ ≥ 0,93), либо расширять модель динамикой (флюид с очередью и триггером). Последнее **не сделано**.
- Здоровая ветвь вблизи 0,93: прототип не проверял (при триггере ×2 отказ уже с 0,6).

### 4.4 Допущения и когда они нарушаются

1. Пуассоновский входной поток попыток с интенсивностью λ_eff. Нарушается: повторы приходят с фиксированной задержкой T+d или d после неудачи, поток коррелирован с состоянием системы; всплески (триггер) создают нестационарный вход.
2. Независимость попыток одного запроса. Нарушается: при перегрузке неудачи сильно коррелированы (очередь длинная для всех).
3. Стационарность (квазистатика): время релаксации очереди много меньше времени изменения q. Вблизи спинодалей релаксация критически замедляется; переходы между ветвями — нестационарные.
4. Экспоненциальное обслуживание (формулы замкнутые только для Exp). LogN (cv = 2) и Pareto: M/G/c не имеет простых замкнутых формул времени ожидания; **модель неприменима, расширение не делалось** (приближения Allen–Cunneen и т. п. не открывались).
5. FIFO. LIFO/ALIFO: P(W+S ≤ T) другое (при перегрузке LIFO обслуживает в первую очередь свежие запросы, поэтому хвост и p99 другие); модель неприменима.
6. Конечная очередь K: вариант K = 128 учтён точно для пуассонова входа; мгновенные отказы считаются неуспехом и повтор в той же схеме (задержка d, без орбиты).
7. D = off. Для D = on осиротевшие попытки не обслуживаются, ρ_eff определяется иначе (обслуживаются только живые попытки, причём доля зависит от очереди); модель неприменима, расширение не делалось.
8. R2/R3 (случайная выдержка и бюджет) в модель не входят: джиттер и token bucket меняют структуру потока; модель неприменима.
9. Конечный масштаб (c = 8): флуктуации не пренебрежимы; детерминированная модель даёт спинодали, а реальные пороги по конечному горизонту смещены (см. 4.3).
10. Попытки, получившие ответ после таймаута, считаются неудачными (по §2 спецификации ответ после t+T не засчитывается). Уточнить в src/.

## 5. Расхождения и неоднозначности спецификации

1. **K**: в §3 «очередь ёмкости K» — принято K мест ожидания, всего c+K. Если в `src/` K — всего мест в системе, числа в 4.2 сдвигаются (мало: около насыщения). Зафиксировать в DECISIONS.md.
2. §8: «q(λ_eff) через время ожидания M/M/c» не определяет поведение при ρ_eff ≥ 1. Принято s = 0 (q = 1); функция F непрерывна при ρ_eff → 1.
3. V3: условие «P(занят) = ρ» верно при ρ < 1 для классической политики; формула E[N] выведена мной, книги Фалина/Артахело не открывались.
4. §4: «при R1 существует ρ < 1 с P_A > 0» выполняется тривиально (ρ ≥ 0,35 в прототипе); но критерий «Δ > 0» сильно зависит от триггера (4.2).
5. §6 протокол B: ρ = 1,05 в течение 400 при K = 128 гарантирует заполнение очереди (прототип: да).
