## 3. Итоги по гипотезам на pilot (оценки pilot, не результаты основного анализа)

Подготовка: pilot части 4 — одни и те же 40 реплик (CRN) для всех конфигураций, поэтому оценки конфигураций коррелируют; ДИ порогов построены в предположении независимости (D-011, D-018). Для основного прогона CRN не применяется.

### H1 (устойчивость рейтинга, τ Кендалла между Exp и LogN)
- Формулировка в PREREGISTRATION («24 конфигурации R×Q×D без R0») внутренне противоречива: R1–R3 × Q3 × D2 = 18, с R0 = 24 (S5).
- Результат по буквальной формулировке: τ-b(Δ) = 0,973, ДИ по ячейкам [0,884; 1,000] (18 ячеек); 0,889 [0,668; 1,000] (24). Критерий отвержения H1 (нижняя граница ≥ 0,8) для 18 ячеек формально выполняется, то есть «рейтинги совпадают». Но это артефакт вырождения: 14 из 18 ячеек имеют Δ = 0 при обоих S (доля связок 0,60 после округления до 0,01), τ-b считается по несвязанным парам и в основном различает «активные против неактивных», а это разбиение не зависит от S.
- По 4 активным ячейкам (R1/R2 × FIFO × D): τ-b = 0,667 [−1,000; 1,000] (при 4 точках ДИ бессодержателен). Δ при Exp / LogN / Pareto: R1/off 0,521 / 0,342 / 0,567; R1/on 0,258 / 0,044 / 0,445; R2/off 0,522 / 0,331 / 0,564; R2/on 0,289 / 0,078 / 0,461. Различие рейтингов — только R1 против R2 внутри D (разность R2 − R1 от −0,011 до +0,034, сопоставимо с шумом) (S5).
- Содержательная структура, которую рейтинг по Δ скрывает: относительное остаточное Δ при D = on к D = off — Exp 0,524, LogN 0,182, Pareto 0,800 (S5). То есть выигрыш от передачи срока зависит от распределения обслуживания (наибольший при LogN cv = 2), а R1 против R2 — нет.
- Непрерывные метрики дают менее вырожденный ответ: τ-b(L_A) = 0,892 [0,732; 0,986], τ-b(H) = 0,817 [0,589; 0,973] (18 ячеек); для 24: 0,809 [0,624; 0,946] и 0,696 [0,444; 0,879] (S5). Их порядок среди неактивных ячеек определяется шумом на уровне 0,003 (L_A, LIFO/ALIFO: 0,0026–0,0032, S6); ДИ по ячейкам не учитывает шум реплик.
- Вывод: H1 в нынешней формулировке на pilot не информативна (ответ определяется вырожденными нулями).

Предложение H1′ (ПРЕДЛОЖЕНИЕ, не принято; сформулировано ПОСЛЕ просмотра pilot, подгонки под основной прогон нет; pilot-данные для этого допустимы, правило 4; решение до заморозки): варианты, из которых автор выбирает один по принципу, а не по результату: (a) единица анализа — 12 активных ячеек; мера — влияние S на эффект D: отношение Δ_on/Δ_off по S с bootstrap-ДИ, H1′ подтверждается, если ДИ разности отношений Exp и LogN не содержит 0 (pilot: 0,524 против 0,182); (b) сохранить τ-b, но на непрерывной метрике L_A по 24 ячейкам, с bootstrap по репликам и ячейкам, критерий нижней границы 0,8 (pilot: 0,809 [0,624; 0,946], то есть исход неопределён); (c) сообщать τ-b по Δ только как описательное, с обязательной пометкой о доле связок.

### H2 (комбинация R3 и ALIFO)
- Контраст C = Δ(R3,ALIFO) − Δ(R3,FIFO) − Δ(R2,ALIFO) + Δ(R2,FIFO): C > 0 в 6 из 6 ячеек (D, S), диапазон 0,078–0,564; он равен Δ(R2,FIFO), так как три других Δ ≈ 0 (S6). Критерий «ДИ ниже 0» недостижим по построению (Δ ≥ 0, обе меры по отдельности уже обнуляют Δ): H2 непроверяема по Δ.
- По непрерывной потере goodput L_A(ρ ≤ 1), bootstrap по репликам: C = +0,1173 [+0,1058; +0,1289]; R3 − R2 внутри FIFO: −0,1168 [−0,1284; −0,1055]; ALIFO − FIFO внутри R2: −0,1424 [−0,1541; −0,1317]; R3 − R2 внутри ALIFO: +0,0005 [+0,0001; +0,0008] (S6). Результат противоречит ожиданию «комбинация сильнее»: каждая мера по отдельности даёт большой эффект, вместе они выходят на пол (L_A ≈ 0,003), и R3 поверх ALIFO не улучшает L_A (разность положительна, но 0,0005 практически нулевая). По усилению при ρ = 0,9 (протокол A): R2/ALIFO 1,028, R3/ALIFO 1,002; wasted 0,010 и 0,006 (S6), то есть R3 слегка снижает усиление и wasted.
- Предложение H2′ (ПРЕДЛОЖЕНИЕ, после просмотра pilot, не принято): сравнивать R3 против R2 отдельно внутри ALIFO и отдельно внутри FIFO на непрерывных метриках (L_A, усиление, wasted) с заранее заданным порогом практической значимости (например 0,01 по L_A), без контраста взаимодействия по Δ. Факт, что pilot показывает противоположный знак, фиксируется: H2′ при этом могла бы быть «не подтверждена».

## 4. Предложения по критерию, метрикам и области ρ > 1 (ПРЕДЛОЖЕНИЯ, не приняты)

1. **Критерий отказа.** Основная область ρ ≤ 1: без изменений, g < θ. Для ρ > 1 (вспомогательная область) использовать g < θ·min(1, 1/ρ), совпадающий с g < θ при ρ ≤ 1. Основание: при простом критерии у всех 60 неактивных ячеек пороги лежат у ρ ≈ 1/θ = 2 (медиана ρ_fold 1,98, диапазон [0,95; 2,01]) и A ≈ B: это порог тривиальной перегрузки (g ≈ 1/ρ), а не гистерезис. При нормированном критерии ρ_fold цензурирован справа (до 2,5) у 48 из 72 конфигураций (у 48 из 60 неактивных), N1 = 12 и N2 = 10 совпадают с основной областью (S3). Критерий введён после просмотра pilot; на основном анализе меняет только вспомогательные таблицы.
2. **Метрики-спутники** (в таблицах рядом с Δ; непрерывные, не имеют эффекта пола у Δ): L_A, L_B = ∫(min(1,1/ρ) − g)dρ по [0,2; 1,0]; H = ∫|g_B − g_A|dρ; wasted; усиление; ограниченное среднее времени восстановления с долей цензурированных. Уровни L_A (S=Exp, D=off): R0/FIFO 0,0146; R3/FIFO 0,0451; R1/FIFO 0,1500; R1/LIFO 0,0027; R1/ALIFO 0,0026; R3/ALIFO 0,0032 (S6). Они упорядочивают конфигурации с Δ = 0: R3/FIFO хуже R0/FIFO, оба хуже LIFO/ALIFO. Оговорки: L и H имеют положительный пол ≈ 0,003 (H смещена вверх из-за |·|); время восстановления ограничено снизу ≈ W (D-008).
3. **Область ρ > 1** — только вспомогательная, помечена «область перегрузки»; в B при ρ_test > 1,05 смысл протокола меняется (нагрузка повышается), проверка B′ (перегрузка 2,6) на 36 конфигурациях даёт те же пороги (pilot_runs_4.md п. 2, из файла). Из этого следует: Δ_ext не расширяет набор активных ячеек (N1_ext = 13 против 12; добавленная — R0/FIFO/on/Pareto 0,008 [0,002; 0,015], микросдвиг; S3).
4. **N1 против N2.** N2 (Δ ≥ 0,1) устойчивее: классификация по точечным порогам совпадает с R = 40 в 72 из 72 уже при R = 8, 16, 24 (S4). N1 чувствителен к микросдвигам (пример выше). Для таблиц предлагаю сообщать оба.

Оценка грубая: она не учитывает более длинные прогоны при H_rec = 6000 (прирост времени не измерялся), разное число точек уточнения и то, что скорость сильно зависит от загрузки машины (17–70 задач/с). Закладывать 3–5 ч. Расход seed'ов main ≈ 3,5·10⁵ из доступных.

Обоснование R: на опорной ячейке полуширина ДИ Δ при R = 40 равна 0,0088, при 100 — 0,0054 (S9); различия между активными ячейками (например D = on против off при LogN: 0,044 против 0,342; R2 − R1 при on: +0,016…+0,034) больше при R = 40, мелкие эффекты R1 против R2 (≤ 0,034) различимы при R = 100. Скрининг-классификация надёжна уже при R = 8 (72/72, S4), но ДИ при R = 8 недопокрывают (0,92–0,93; pilot4_sens.txt, из файла). Правило эскалации (предложение): ячейка, не входящая в 12 активных, но с точечными Δ ≥ 0,1 и ρ_fold < 1 на грубой сетке при R = 40, дозапускается до R = 100 (симметрия правила).

## 6. Открытые риски и что не проверено

- **Размах эффекта.** Метастабильность (Δ > 0) обнаружена только у R1/R2 × FIFO. LIFO, ALIFO (θ_q = 0,25–0,75), R3, R0 при ρ ≤ 1 отказов не дают; при агрессивном клиенте (m = 6, T = 5) тоже (pilot_runs_4.md п. 4, из файла). Это результат модели, но он определяет структуру статьи (H1/H2 в текущем виде вырождены).
- **План анализа.** OLS «по 72 оценкам с весами, обратными дисперсии bootstrap» (PREREGISTRATION п. 3) ломается: у 55 ячеек, где оба порога цензурированы справа, Δ = 0 и дисперсия bootstrap = 0 (d_lo = d_hi = 0, S3). Нужно правило (регрессия на 12 активных или Тобит/цензурированная регрессия), иначе веса не определены. Не решено.
- **Триггер.** Единый триггер выбран по одной ячейке (R1/FIFO/off/Exp), вдобавок крайний слабый элемент сетки. Δ чувствительна: 0,423–0,591 при m_s 1,75–1,25 (S7). Допустимость для R2/FIFO/on/LogN (Δ = 0,078) и R1/FIFO/on/LogN (0,044) < 0,1 — эти ячейки N1, но не N2.
- **Длина перегрузки B** 1000 не подтверждена автором (D-017); данные частей 1–3 с 400 не смешиваются с частью 4 (другой config_hash: 148eb8d011551aa1 против b998d5446ecf3b38 для опорной).
- **Горизонт.** ρ_release зависит от H_rec (+0,053 между 1500 и 6000); H_rec-чувствительность проверена только на части 1 (перегрузка 400) и на одной ячейке.
- **Модельные.** Условие K/c > T (по двум точкам); поведение при D = on у LIFO/ALIFO (просроченные записи занимают место, D-014); один сервис, синтетические параметры.
- **Механизмы** (wasted, очередь, просроченные старты) выведены из 10 реплик и описательны, причинность не доказана (pilot_runs_3.md/4.md).
- **Данные.** (i) `sessions.jsonl` содержит записи о 861 746 задачах из 1 073 746: у 212 000 задач записи сессии нет (остановленный вручную запуск agg, pilot_runs_4.md; сами результаты полны, check_complete: complete); (ii) во всех строках `git_commit` с суффиксом `-dirty` (код pilot не закоммичен; для main нужен чистый коммит и `requirements.lock`); (iii) общие случайные числа в части 4 коррелируют оценки конфигураций; (iv) в тексте PREREGISTRATION «24 конфигурации R×Q×D» ошибочно; (v) MODEL_SPEC §6 содержит сетку 0,40–1,00, что цензурирует ρ_release слева у 4 активных ячеек.
- **Не проверено:** покрытие ДИ на конфигурациях, отличных от опорной; ρ_release для LogN/Pareto при H_rec ≠ 1500; влияние множественности на N1 (поправка не вводилась); T-, K-чувствительность на 12 ячейках (только опорная); поведение при θ_q ∈ (0,625; 1) и θ = 0,95 для ALIFO; расширение E2.
