## A. Скрининг 72 конфигураций (триггер 1,5; 25)
Сетка: ρ = 0,20…1,00 шаг 0,05 (17 точек), протоколы A и B, **R = 8 реплик на точку** (в задании 20; из-за бюджета, п. 0). Без раунда уточнения (шаг только 0,05; пороги грубые). Спецификации: `pilot3_scr.yaml` (54 конфигурации R ∈ {R1, R2, R3} × Q × D × S; для 10 конфигураций части 2 используются реплики < 8, их результаты по 40 репликам (`pilot2_configs.csv`) приводятся рядом как проверка метода скрининга), `pilot3_r0.yaml` (18 конфигураций R0 × Q × D × S: контроль, только ρ ∈ {0,80; 0,90; 0,95; 1,00}, 8 реплик; R0/FIFO/off/Exp дополняется точкой ρ = 1,00).

Оценка порогов: `src/thresholds.py` (D-011), bootstrap 2000, seed 11; Δ без отсечения по 0.

Классификация конфигурации (заранее):
- **N1 (основной признак «метастабильность есть»):** ρ_fold не цензурирован справа и нижняя граница 95 % ДИ Δ > 0.
- **N2 (практический, как в частях 1–2):** ρ_fold не цензурирован справа и Δ (точечная) ≥ 0,1.
- Вырождения: (a) «нет отказов»: P_A = P_B = 0 на всей сетке (оба порога цензурированы справа); (b) «срыв без гистерезиса»: ρ_fold < 1, но нижняя граница ДИ Δ ≤ 0 (или Δ < 0,1 при N2); (c) ρ_release цензурирован слева (отказ в B при любом ρ ≥ 0,20).
Доля цензурированных порогов считается по 54 × 2 = 108 порогам не-R0; R0 — отдельно: контроль = P_A = P_B = 0 при ρ ≤ 0,95 (допускается единичный шум, как в части 1: 0,5 % и 1,5 % при ρ = 0,95), порог по 4 точкам не оценивается.

Таблицы: по факторам R × Q × D × S (число N1 и N2 из 54, маргинальные таблицы по каждому фактору и по парам R × Q, Q × D, Q × S).

**H1.** Единица — ячейка R × Q × D (в PREREGISTRATION написано «24 конфигурации без R0»; это несовпадение: R × Q × D = 18 без R0, 24 с R0 — отмечается). Считаются: число ячеек, невырожденных (N1) при S = Exp, при S = LogN, при обоих; τ-b Кендалла между векторами Δ (Exp) и Δ (LogN) (а) по 18 ячейкам без R0, (б) по 24 с R0 (Δ = 0 по контролю), (в) по ячейкам, невырожденным хотя бы в одном S; индикативный ДИ — bootstrap по ячейкам (2000), эксплораторный (в препрегистрации bootstrap по репликам не определён). Совпавшие нули (ties) завышают τ при вырождении — это указывается.
**H2.** Для каждой пары (D, S) (6 ячеек) контраст взаимодействия C = Δ(R3,ALIFO) − Δ(R3,FIFO) − Δ(R2,ALIFO) + Δ(R2,FIFO). Считается число ячеек, где все 4 Δ невырождены (N1), где R3×ALIFO невырождена, где обе одиночные меры (R3/FIFO и R2/ALIFO) дают Δ ≈ 0. Ожидание, записанное до просмотра данных: Δ ≥ 0 по построению, поэтому при обнулении Δ каждой одиночной мерой контраст равен +Δ(R2,FIFO) > 0 механически (эффект пола); тогда знак «ниже 0» недостижим и H2 в текущей формулировке не проверяема. Это логический вывод, а не результат данных; проверяется по таблице.

## B. LIFO/ALIFO: диагностика причины
Опорная R1/off/Exp. Дополнительные ρ: 1,05; 1,10; 1,25; 1,50; 2,00, протоколы A и B, **20 реплик**, Q ∈ {FIFO, LIFO, ALIFO(θ_q = 0,5)} (`pilot3_diag_hi.yaml`; ρ = 0,9 и 1,0 берутся из части 2, 40 реплик). Чувствительность ALIFO: θ_q ∈ {0,25; 0,75}, ρ = 0,20…1,00 шаг 0,05 по **10 реплик** (`pilot3_diag_thq.yaml`) и ρ ∈ {1,05; 1,10; 1,50} по 20 реплик (`pilot3_diag_thq_hi.yaml`).
Выход: P_A, P_B, g_final, среднее и максимум длины очереди в итоговом окне, доля впустую потраченной работы, усиление, доля отклонённых попыток по ρ, Q, θ_q; ρ* = наименьшее проверенное ρ, при котором доля отказов ≥ 0,5 (или «не достигнуто до 2,0»). Механизм (эксплораторно): повторное воспроизведение прогонов по сохранённым seed'ам (`analysis/pilot3_diag.py`, детерминировано, V5) со сбором траекторий: длина очереди и g(t) по времени, возраст попытки в момент начала обслуживания, доля стартов с просроченным сроком, число «осиротевших» записей в очереди на конец. Что именно показывать, определяется структурой задачи, а не просмотром результатов; выводы помечаются эксплораторными.
Гипотеза до просмотра данных (из чтения кода `src/model.py`, D-005, не из данных): ALIFO переключается на LIFO при длине очереди > θ_q·K; ожидание в FIFO-режиме достигает θ_q·K/c; при θ_q·K/c < T (θ_q < T·c/K = 0,625) запросы в FIFO-режиме успевают обслужиться до таймаута, при θ_q > 0,625 — нет. Поэтому ожидается: метастабильность появится при θ_q = 0,75 и не появится при θ_q = 0,25. Если не подтвердится, это результат.

## C. Чувствительность опорной конфигурации (R1/FIFO/off/Exp)
По одной переменной за раз, остальное как в базе; 40 реплик, ρ = 0,20…1,00 шаг 0,05, один раунд уточнения (`experiments/refine_grid.py`, шаг 0,025, окно ±0,075 вокруг порога отдельно по P_A и P_B, 40 реплик, lo = 0,20, hi = 1,00, правило S1 из части 1; считается только по P_A и P_B).
- T ∈ {5; 20} (`pilot3_sens_TK.yaml`), K ∈ {64; 256} (`pilot3_sens_K.yaml`), протоколы A и B. База (T = 10, K = 128, θ = 0,5, триггер (1,5; 25)) берётся из имеющихся данных, реплики < 40.
- Сила триггера по превышению (m_s − 1) = 0,5: ×0,5 → m_s = 1,25; ×1,5 → m_s = 1,75; D_s = 25 (`pilot3_sens_trg.yaml`). Только протокол A: протокол B от триггера не зависит (D-015), берётся из базы. Для m_s = 1,25 переиспользуются реплики `diag_A` (40 реплик, ρ = 0,30…0,95), добавляются ρ = 0,20; 0,25; 1,00.
- θ ∈ {0,3; 0,7}: **новые прогоны не делаются** (отклонение, бюджет). θ входит в модель только через флаг `failed = int(g_final < θ)` (`src/protocols.py`, `summarize`); траектория и g_final от θ не зависят. Поэтому для θ ∈ {0,3; 0,7} флаг пересчитывается по g_final имеющихся прогонов базы (реплики < 40, все ρ базы, включая уточнённые). Эквивалентность проверяется прямым запуском 24 прогонов с изменённым θ (в процессе, без записи в этап; сравнение g_final и failed). Для θ нет раунда уточнения вокруг новых порогов (точки только базы).
Критерий допустимости (заранее): Δ (точечная) ≥ 0,1 и ρ_fold не цензурирован справа (ρ_fold < 1,0); дополнительно сообщается нижняя граница ДИ Δ. Допустимость сохраняется для переменной, если выполняется при **обоих** проверяемых уровнях. Для T, K сравнение ρ_release и ρ_fold с mean-field (`analysis/theory.py`: `MFParams(c = 8, k_queue = K, t_out = T)`, θ = 0,5; спинодали по сетке ρ шаг 0,005 и бисекция): ρ_release^MF и ρ_fold^MF (последняя — спонтанная спинодаль; не равна ρ_fold протокола A, D-001). Разность sim − MF сообщается как есть, пороги δ не назначаются (H3 на G3). Горизонт H_rec = 1500 в сравнении фиксирован (ρ_release зависит от H_rec, часть 1).

## D. Покрытие bootstrap-ДИ порогов (опорная, триггер (1,5; 25))
Окна на шаге 0,02: протокол A ρ ∈ {0,80; 0,82; …; 0,90} (6 точек), протокол B ρ ∈ {0,29; 0,31; …; 0,39} (6 точек) (`pilot3_cov_A.yaml`, `pilot3_cov_B.yaml`). Окна выбраны по данным частей 1–2 (опорная) и покрывают P от ≈ 0,05 до ≈ 1; вне окон оценка порогов не делается (одинаковый эстиматор для «истины» и подвыборок: `estimate_delta`, bootstrap 2000, окно из 6 точек на протокол).
- «Истина» (оценка плотных данных): replicate 100…399 (новые 300 реплик на точку), независимы от подвыборок.
- Подвыборки: replicate 0…99 (имеющиеся, 100 на точку); 200 подвыборок по R = 40 реплик на точку, без возвращения (в задании «независимые»: независимой от «истины» является выборка; сами подвыборки из пула 100 перекрываются, MC-ошибка доли покрытия поэтому больше биномиальной ±0,03; отмечается). Дополнительно, **эксплораторно**: (i) то же для R = 8 (размер скрининга); (ii) параметрическая версия: 1000 независимых подвыборок Bin(R, P̂_truth) на каждую точку, где P̂ — доля отказов «истины».
- Метрика: доля ДИ (перцентильный, 95 %), содержащих «истину», отдельно для ρ_fold, ρ_release, Δ; доверительный интервал доли — Уилсона. Заранее: покрытие < 0,90 трактуется как недопокрытие (ДИ — приближённые), 0,90–0,98 как приемлемое; промежуточные пороги не назначаются. Известное смещение: «истина» оценена по 300 репликам (SD ≈ 0,37 SD при 40), это немного занижает покрытие (≈ на 1 п.п.); не корректируется.
