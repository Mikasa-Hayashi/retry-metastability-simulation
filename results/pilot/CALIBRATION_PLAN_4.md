## 0. Seed'ы и общие случайные числа
- Блок общих случайных чисел (CRN): seed = 100000 + номер реплики (резерв 100000–109999). Реплика r любой конфигурации, любого ρ и протокола использует один и тот же seed (D-009: потоки входа, обслуживания и джиттера выводятся из seed; входной поток одинаков при разных ρ). Применяется во всех сравнениях конфигураций между собой (пп. 1–4, 6, 7). Следствие: оценки разных конфигураций положительно коррелируют, ДИ их разностей уже, чем при независимых блоках; внутри конфигурации точки ρ тоже коррелируют по реплике (это не нарушает bootstrap «по репликам внутри точки», но доли отказов соседних точек не независимы). Ключ возобновления (config_hash, ρ, протокол, seed) остаётся уникальным.
- Независимые блоки (эталоны, пул покрытия): seed = следующий свободный номер, начиная с 110000 (D-015 для этих задач: seed = 110000 + порядковый номер среди независимых задач).
- Отклонение от D-015: seed в CRN-блоке не равен «stage_base + порядковый номер задачи» (по решению автора, общие случайные числа). Реализация: `experiments/make_grid_p4.py` (новый файл, `src/runner.py` не менялся), запись D-017.
- Блоки записываются в MANIFEST после прогона. Анализ выбирает данные части 4 по seed ≥ 100000 (старые строки с теми же config_hash не смешиваются: тот же конфиг, но другие seed'ы и другой overload_len → другой хэш для B-конфигураций).

## 1. Скрининг без урезаний (`pilot4_scr.yaml`)
72 конфигурации R{0,1,2,3} × Q{FIFO,LIFO,ALIFO} × D{off,on} × S{Exp,LogN,Pareto}; ρ = 0,20…1,00 шаг 0,05 (17 точек); протоколы A и B; 40 реплик (CRN 0…39). Далее уточнение шагом 0,01 в окне ±0,05 вокруг порога для невырожденных (порог не цензурирован на заданной сетке), отдельно по P_A и по P_B, 40 реплик (правило `refine_rhos` из `src/runner.py`, смотрит только на `failed`, ρ, протокол). Расчётно 97 920 задач до уточнения.
Классификация (как в части 3, заранее): N1 = ρ_fold < 1 и нижняя граница 95 % ДИ Δ > 0; N2 = ρ_fold < 1 и Δ ≥ 0,1. Вырождения: «нет отказов», «срыв без гистерезиса», «B всегда в отказе». Пороги и ДИ — `src/thresholds.py` (D-011), bootstrap 2000. Δ в области ρ ≤ 1 (правое цензурирование на 1,0).

## 2. Расширенная область перегрузки (`pilot4_ext.yaml`)
Те же 72 конфигурации и те же реплики; ρ = 1,05 и 1,1…2,5 шаг 0,1 (16 точек), A и B. Расчётно 92 160 задач до уточнения. Уточнение: порог по всей сетке 0,20…2,50 (данные скрининга и расширения вместе), если порог ≤ 1,0 — шаг 0,01, окно ±0,05 (этап п. 1), если порог > 1,0 — шаг 0,02, окно ±0,10; цензурированные пороги не уточняются.
Две величины Δ (заранее):
- Δ(ρ ≤ 1): по данным ρ ≤ 1,0, правое цензурирование на 1,0 (определение MODEL_SPEC §6).
- Δ_ext: по данным ρ ∈ [0,20; 2,50], правое цензурирование на 2,5 (область ρ > 1 — «область перегрузки»; помечается так в таблицах и отчёте).
Замечание о смысле протокола B при ρ_test > 1,05 (логическое, не из данных): в B нагрузка после перегрузки 1,05 не снижается, а повышается; B и A различаются только предысторией. Поэтому Δ_ext при ρ_test > 1,05 измеряет разницу состояний, а не «снижение нагрузки». Эксплораторно (п. 2б, после основных прогонов, при наличии времени): протокол B' с перегрузкой ρ = 2,6 вместо 1,05 для ρ_test ≥ 1,05 (`proto.overload_rho`), 40 реплик, тег `p4_bp`.
Критерий отказа при ρ > 1 (эксплораторно): простой критерий g < θ при ρ > 2 тривиален (g ≈ 1/ρ < 0,5). Предлагается нормированный: failed_norm = g_final · max(1, ρ) < θ_n, θ_n = 0,5 (эквивалентно g < θ · min(1, 1/ρ); при ρ ≤ 1 совпадает с простым критерием). Расчёт — пересчёт флага по `g_final` (g_final от θ не зависит, подтверждено в части 3), чувствительность θ_n ∈ {0,3; 0,5; 0,7; 0,9}. Пороги и Δ_ext по нему считаются теми же функциями. Уточнение для нормированного критерия (эксплораторно) — отдельным раундом по тем же правилам, если порог не цензурирован и лежит вне уже плотных участков.
Что смотрим: где A ≈ B (|P_A − P_B| малы при всех ρ, Δ_ext ≈ 0), где Δ_ext > 0; существуют ли пороги ρ_fold, ρ_release (нецензурированные) у LIFO/ALIFO/R3.

## 3. Непрерывные метрики деградации (`analysis/pilot4_metrics.py`)
По данным пп. 1–2 (CRN, реплики 0…39), только на общей грубой сетке (ρ кратно 0,05 при ρ ≤ 1,0; кратно 0,1 при ρ > 1,0, плюс 1,05) — одинаковые узлы у всех конфигураций, чтобы метрики были сопоставимы (уточнённые точки в интегралы не входят). Метрики (для каждой конфигурации):
- (а) площадь петли гистерезиса H = ∫|g_B(ρ) − g_A(ρ)| dρ (трапеции по узлам; g — среднее по репликам g_final) на [0,2; 1,0] и на [0,2; 2,5];
- (б) потерянный goodput L = ∫(g*(ρ) − g(ρ)) dρ, g*(ρ) = min(1, 1/ρ), отдельно для A и B, на тех же двух интервалах;
- (в) доля впустую потраченной работы и усиление нагрузки (amplification) при ρ ∈ {0,7; 0,9; 1,0} (A и B);
- (г) p99 (по успешным первичным запросам итогового окна) и время восстановления при тех же ρ: для времени восстановления сообщается доля цензурированных (recovery_censored) и среднее с цензурой на горизонте H_rec (ограниченное среднее; Каплан–Мейер на этапе плана не применяется).
ДИ: bootstrap по репликам, 2000 повторов, одинаковые индексы реплик для всех ρ и обоих протоколов (CRN → парность), перцентильный 95 %. Для разностей конфигураций — тот же набор индексов у обеих.

## 4. Факторы агрессивности клиента (`pilot4_agg.yaml`)
R{1,2,3} × Q{FIFO,LIFO,ALIFO} × D{off,on} × S{Exp,LogN} × число повторов m{3,6} (`retry.max_retries`) × T{5,10} × θ_q{0,25; 0,5; 0,75; 1,0} (θ_q только для ALIFO; у остальных Q — 0,5) = 288 конфигураций, из них 36 (m = 3, T = 10, θ_q = 0,5) совпадают с пп. 1–2 и не дублируются. ρ = 0,20…1,00 шаг 0,05 и 1,05…1,50 шаг 0,05, A и B, 40 реплик (CRN). Расчётно ≈ 620 тыс. задач до удаления дубликатов; время ≈ 3–4 ч при 7 процессах. Уточнение — по тому же правилу, что в п. 1 (шаг 0,01, ±0,05 при пороге ≤ 1,0; шаг 0,05 уже достаточный выше 1,0, там без уточнения), только для невырожденных. Ожидание до просмотра данных: θ_q = 1,0 для ALIFO эквивалентен FIFO (переключение при длине > K никогда не наступает), при K/c = 16 > T (T = 5, 10) таймауты по очереди возможны. Выход: число N1/N2 и Δ по уровням (m, T, θ_q) отдельно для ячеек LIFO, ALIFO и R3; какие уровни дают информативные (N1) Δ у LIFO/ALIFO/R3.

## 6. Чувствительность прямыми прогонами (`pilot4_sens.yaml`)
Опорная R1/FIFO/off/Exp. Варианты по одной переменной: θ ∈ {0,3; 0,5; 0,7}; T ∈ {5; 10; 20}; K ∈ {64; 128; 256}; m_s ∈ {1,25; 1,5; 1,75} (только A; B от триггера не зависит, берётся из базы). ρ = 0,20…1,00 шаг 0,05 и 1,1…1,5 шаг 0,1, 40 реплик (CRN), уточнение шагом 0,01 ±0,05 вокруг порогов (для цензурированных справа на 1,0 — окно [0,95; 1,00], правило `refine_rhos`). θ — прямыми прогонами (отдельные config_hash), не пересчётом; ожидание (из кода, не из данных): при тех же seed'ах траектории совпадают, различается только флаг. Сравнение с mean-field `analysis/theory.py` — как в части 3 (разности sim − MF без порогов δ).
Покрытие bootstrap-ДИ (`pilot4_cov_*.yaml`): независимые блоки (seed ≥ 110000). Окна ±0,05 вокруг порогов опорной конфигурации с шагом 0,01 (11 точек на протокол; центры берутся из порогов опорной конфигурации по данным п. 6, т. е. только по P_A, P_B; фиксируются в `pilot4_cov_*.yaml` до прогона). «Эталон»: 400 реплик на точку (блок T). Пул для подвыборок: 2000 независимых реплик на точку (блок P, не пересекается с эталоном). Подвыборки R = 40 (и 8 — эксплораторно): 1000 случайных подвыборок без возвращения из пула; параметрические: 1000 подвыборок Bin(R, P̂_эталон) на точку. Покрытие = доля ДИ (перцентильных 95 %, bootstrap 2000), содержащих эталонное значение, с ДИ Уилсона; заранее: < 0,90 — недопокрытие, 0,90–0,98 — приемлемо. Подвыборки из пула перекрываются слабо (40 из 2000), но не независимы строго; указывается.

## 7. Насыщение или эффект повторов (`pilot4_r0sat.yaml`, `pilot4_r0sat_h.yaml`)
R0 и R3 (FIFO, off) × S{Exp, LogN, Pareto}; ρ = 0,90…1,05 шаг 0,01; A и B; 100 реплик (CRN 0…99); P_A, P_B, g_final, очередь, доля просроченных стартов. Критерий (заранее): «насыщение», если кривые P(ρ) у R0 и R3 различаются не более чем на ±0,1 по доле отказов (и ДИ порогов перекрываются), «эффект повторов», если R3 срывается при ρ заметно ниже, чем R0. Эксплораторно: R0, R3 (Exp) при H_rec = 3000 и 6000 — если порог R0 смещается к 1,0 с ростом горизонта, это критическое замедление у ρ = 1, а не бистабильность.
