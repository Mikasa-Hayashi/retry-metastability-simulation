## 2. Единый триггер: заранее заданный критерий
Конфигурация «допустима при триггере» по тому же правилу, что в части 1: Δ (точечная) ≥ 0,1 и ρ_fold не цензурирован справа.

Конфигурация попадает в список «проверить сетку триггеров», если при (1,5; 25) выполняется хотя бы одно: Δ < 0,1; ρ_fold цензурирован справа; ρ_release цензурирован слева. Для них прогоняется протокол A на сетке 12 триггеров части 1 (m_s ∈ {1,5; 2; 3; 4} × D_s ∈ {25; 50; 100}); ρ = 0,20…1,00 шаг 0,05, 40 реплик, уточнение как в п. 1. Протокол B от триггера не зависит и берётся из п. 1.

**Критерий «единый слабый триггер (1,5; 25) допустим»:** из 10 конфигураций не более 2 недопустимы (Δ < 0,1 или ρ_fold цензурирован справа), при этом не более 1 с ρ_fold, цензурированным справа. Порог 2 из 10 выбран заранее (20 %); для основной сетки это ≤ 14 из 72 конфигураций, остальные сохраняют точечные Δ.

**Если критерий не выполнен:** общий более сильный триггер = самый слабый по порядку E (CALIBRATION_PLAN.md) триггер, при котором среди проверяемых конфигураций, объединённых с опорной, не более 1 недопустимой и опорная допустима. Затем для него A-прогон на остальных (не проверявшихся) конфигурациях из 10, и итоговое требование то же: не более 2 недопустимых из 10. Если и так не выполняется, не подбирать на ходу, сообщить человеку (варианты: T, K, θ, разные триггеры недопустимы по правилу единого триггера).

Отдельно сообщается: у какой доли конфигураций ρ_fold(1,5; 25) лежит выше ρ_fold спонтанной спинодали mean-field 0,9285 (THEORY.md), то есть триггер ничего не сдвигает. Это диагностика, в критерий не входит.

## 3. «Самопроизвольные восстановления» в протоколе B
Опорная конфигурация (триггер в B не участвует). Протокол B, ρ = 0,5:
- (a) c = 8, K = 128, H_rec = 1500: 300 реплик (имеющиеся + докрутка до 300); дополнительно ρ = 0,4 и 0,6 по 200 реплик;
- (b) c = 4, K = 64: 300 реплик; (c) c = 16, K = 256: 300 реплик (K/c = 16, как в основной);
- (d) c = 8, H_rec = 6000: 200 реплик.

Определение: восстановление = failed_B = 0 при ρ ≤ 0,6 (в этом режиме ожидается failed_B = 1). Дополнительно: «возврат» = recovery_censored = 0 при failed_B = 1 (система здорова в какой-то момент, затем снова срыв).

Заранее заданные признаки «объяснимо флуктуациями при малом c»: (i) доля восстановлений убывает с ростом c: p(c = 4) > p(c = 8) > p(c = 16), и ДИ Уилсона для c = 4 и c = 16 не пересекаются; (ii) число восстановлений растёт с горизонтом (d) относительно (a) примерно пропорционально горизонту (постоянный риск выхода из метастабильной ветви; сравнивается как доля 1 − exp(−λ H)); (iii) у восстановившихся g_final близка к 1 (≥ 0,9), то есть это переход между ветвями, а не шум g около θ. Если (i) не выполнен, это не объяснено флуктуациями при малом c: сообщить как открытый вопрос (возможно, свойство модели, а не размера).

## 4. Правило уточнения сетки: сравнение по точности порога
Опорная конфигурация, триггер (1,5; 25). Плотные данные: шаг 0,01 в окнах ρ ∈ [0,76; 0,95] (A) и [0,27; 0,40] (B), 100 реплик на точку (с учётом имеющихся). Затем моделируются схемы, повторяющие адаптивное правило на этих данных с повторной выборкой реплик внутри точек (по R = 40 реплик на точку; 1000 повторений):
- S0: только грубая сетка 0,05;
- S1: грубая + раунд 0,025, окно ±0,075 (часть 1);
- S2: грубая + раунд 0,01, окно ±0,05 (MODEL_SPEC §6);
- S3: грубая + раунд 0,025 ±0,075 + раунд 0,01 ±0,025;
- S4: грубая + раунд 0,01 ±0,03.

Метрики: SD оценки порога по повторениям, смещение относительно оценки по всем плотным данным (100 реплик на всех точках 0,01, та же логистика/изотоника), число прогонов на порог. Критерий выбора, заранее: схема «достаточна», если SD порога ≤ 1,25 × SD схемы S2 (по обоим порогам). Выбирается самая дешёвая по числу прогонов из достаточных. Ограничение: bootstrap-ДИ не пересчитывается заново, сравнивается только разброс точечной оценки.
