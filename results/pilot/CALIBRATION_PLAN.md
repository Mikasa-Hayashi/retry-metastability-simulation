# План калибровки триггера (pilot, seeds 0–99999)

Записан 23.10.2026 до первого прогона. Правило выбора: PREREGISTRATION, «Правило калибровки триггера». Данные основного прогона не используются, seeds 1000000+ не трогаются.

## Опорная конфигурация
configs/base_r1_fifo_off_exp.yaml: c = 8, K = 128, T = 10, R1, FIFO, D = off, S = Exp, θ = 0,5, H_rec = 1500, окно итогового наблюдения 300, W = 100. Меняется только триггер.

## Сетка триггеров (12)
m_s ∈ {1,5; 2; 3; 4} × D_s ∈ {25; 50; 100} (всплеск ρ → m_s·ρ на длительность D_s).

Порядок «слабости» задан заранее по избыточной нагрузке E = (m_s − 1)·D_s (по возрастанию; при равенстве слабее тот, у кого меньше m_s):

| E | триггеры (m_s; D_s) в порядке слабости |
|---|---|
| 12,5 | (1,5; 25) |
| 25 | (1,5; 50), (2; 25) |
| 50 | (1,5; 100), (2; 50), (3; 25) |
| 75 | (4; 25) |
| 100 | (2; 100), (3; 50) |
| 150 | (4; 50) |
| 200 | (3; 100) |
| 300 | (4; 100) |

## Сетка ρ и реплики
Грубая: ρ = 0,30…0,95 шаг 0,05 (14 точек), 40 реплик на точку, протоколы A и B. Протокол B не использует триггер (план: перегрузка 1,05 на 400, затем снижение; проверено тестом tests/test_runner.py::test_protocol_b_independent_of_trigger), поэтому B прогоняется один раз (конфигурация с триггером (4; 50)) и используется для всех триггеров; A прогоняется для каждого из 12 триггеров.

Уточнение (один раунд, experiments/refine_grid.py): для каждого порога, найденного по P_A (отдельно для каждого триггера) и по P_B, добавляются точки, кратные 0,025, в окне ± 0,075 вокруг порога (при цензурировании справа окно [0,875; 0,95], слева [0,30; 0,375]), которых ещё нет в сетке; 40 реплик на новую точку. Уточнение смотрит только на P_A и P_B. Итоговая оценка по объединённым данным.

## Правило выбора
Порог = ρ, где P = 0,5 (src/thresholds.py: логистическая, при разделении изотоническая регрессия, D-011); ρ_fold по A, ρ_release по B; Δ = ρ_fold − ρ_release; bootstrap 2000 повторов.
Допустимый триггер: Δ ≥ 0,1 (точечная оценка) и ρ_fold < 1, то есть порог по A не цензурирован справа (P_A достигает 0,5 при ρ ≤ 0,95). Выбирается самый слабый допустимый по порядку E. Сообщается также нижняя граница ДИ Δ для выбранного. Если допустимых нет, не подбирать на ходу: сообщить и предложить варианты (T, K, D_s).

## Контроли и чувствительность (после выбора триггера)
1. R0 (та же конфигурация, R = R0, выбранный триггер): A и B, ρ = 0,30…0,95 шаг 0,05, 40 реплик; дополнительно ρ = 0,95: всего 200 реплик на протокол (шум R0).
2. H_rec ∈ {1500, 3000, 6000} на опорной конфигурации с выбранным триггером: те же ρ-точки, что и в калибровке (грубые + уточнённые), 40 реплик; для 1500 используются данные калибровки.
3. Мощность: опорная конфигурация с выбранным триггером дополняется до 100 реплик на точку; полуширина bootstrap-ДИ порогов и Δ по подвыборкам R ∈ {20; 30; 40; 60; 100}.
4. Скорость: 72 конфигурации основной сетки с выбранным триггером × (A, B) при ρ = 0,7 и A при ρ = 0,9, 1 реплика (216 задач), 7 процессов.

## Дополнение от 23.10.2026 (после получения таблицы калибровки)
По правилу выбран самый слабый триггер сетки: (m_s = 1,5; D_s = 25), E = 12,5, то есть крайний элемент сетки. Чтобы понять, чем он отличается от отсутствия триггера, добавлен эксплораторный диагностический прогон (теги diag_A): m_s ∈ {1,0; 1,25}, D_s = 25, A, ρ = 0,30…0,95, 40 реплик. Он не участвует в выборе триггера; решение по триггеру принимает человек на G3. Спецификации сеток лежат в experiments/grids/.
